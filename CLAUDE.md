# Backend

NestJS 12 · TypeScript · TypeORM + PostgreSQL · JWT/Passport · Jest · pnpm

- `src/modules/<name>/`: hexagonal layers `domain/` → `application/` → `infrastructure/` and `interface/http/`; `src/shared/` for cross-module code
- Domain imports only `shared`. Use cases depend on `*.repository.port.ts`, never on ORM entities.
- DB schema: `docs/database_schema.md` (ER diagram, FKs, module mapping); DDL source of truth `docs/database/schema.sql`, test data `docs/database/seed.sql`. Tables and FKs are in graphify (`graphify explain "TURNO"`); SQL extraction needs `graphifyy[sql]`
- Tracking: the adaptador (`../adaptador`) posts GPS positions to `POST /tracking/posiciones` (guard `X-Api-Key` = env `ADAPTADOR_API_KEY`); they are pushed to the web panel over Socket.IO, namespace `/tracking`, event `posiciones` (JWT in `auth.token`). Interim virtual GPS per machine: IMEI `'9' + id_maquina`, auto-registered in DISPOSITIVO_GPS/ASIGNACION_GPS on its first position (`TrackingPostgresqlRepository.guardar`). The web map draws a machine's path from `GET /tracking/turnos/:idTurno/recorrido` and `GET /tracking/maquinas/:idMaquina/recorrido?desde&hasta` (max 48 h; `hasta: null` = open, the web appends live positions)
- Alertas de turno: computed from TURNO and TURNO_ESTADO (never stored): shift/journey over 10 h (`E-`/`J-`), auto close (`A-`), MANTENCION-category state (`M-<id_turno_estado>`); `AlertasEnVivoScheduler` diffs the last 24 h right after any TURNO/TURNO_ESTADO write (the turnos repositories emit the in-process event `turnos.cambiaron`, `shared/application/eventos-turnos.ts`) and every 15 s for the time-only 10 h crossing (auto close runs every 30 s), and pushes new ones over Socket.IO, namespace `/alertas`, event `alertas` `{ nuevas, activas }` (JEFE_TURNO/ADMIN only; shared JWT middleware `shared/infrastructure/websocket/autenticar-socket.ts`)
- Estado operacional en vivo: the app posts state changes straight to `POST /turnos/estados` (not via the adaptador); `RegistrarEstadoUseCase` pushes the turn's current state over Socket.IO, namespace `/estados`, event `estados` `{ idMaquina, idTurno, estadoOperacional }` (any role). `/maquinas/flota` includes `estadoOperacional` so the web map colors each machine by category
- Dashboards (module `reportes`, controller `/dashboards`): Metabase OSS runs apart (`cmp-metabase`, guide `docs/metabase.md`) and reads only the views of DB schema `reportes` (migrations 016-022, 024). The web uploads the contractor's monthly EP Excel (only sheet "Base de datos" plus the "Tarifas garantizadas"/"Tarifas diferenciadas" tables of sheet "EP #NN MLC" are read, the number varies per EP, both required; the rest has personal data) and gets signed iframe URLs (env `METABASE_*`). Tariffs go to `reportes.carga_tarifa`, views `v_tarifas_garantizadas`/`v_tarifas_diferenciadas` (Excel column names + `id_carga`). The EP dashboard shows the Excel alone, no comparison with app data (dropped in 021). EP format since #08: "N° Interno" = machine code (`equipo`), "Equipo" = type (`categoria`), "Area" = contractor's free text (`area`, not mapped to app areas), "ID" = `id_excel`. `v_horas_excel`/`v_horometros_excel` use the Excel's own column names and order (quoted: `"N° Interno"`) plus `"Horas Dia"`/`"Horas Noche"` (Diferencia split by clock from the start hour, day 08:00–20:00) and `id_carga`. exceljs drops a formula's cached result when it is 0: the reader treats a formula without result as 0. TEMPORARY: with env `REPORTES_DB_*` set (prod → Aiven, while Metabase reads Aiven) the EP cargas live in that DB (`ConexionReportes`, lazy connection); the uploader is matched there by email, the fleet check stays on the main DB. Remove before the pilot (`docs/metabase.md` §6)
- Mobile app distribution (module `app-movil`, table VERSION_APP, migration 023): PUBLIC endpoints (no session) `GET /app-movil/versiones` (published versions, highest first) and `GET /app-movil/descarga` / `GET /app-movil/versiones/:id/descarga` (302 to a 10-min read SAS; the Blob container `AZURE_STORAGE_CONTAINER_APK`, default `apk`, stays private). ADMIN manages them under `/app-movil/admin/versiones`: publishing is 2 steps, `POST subida` returns a 30-min create/write SAS so the browser PUTs the ~80 MB APK straight to Blob (needs CORS PUT on the storage account for the Frontend origin), then `POST` checks the blob (ZIP header, ≤300 MB) and inserts the row; PATCH notas/publicada (retire), DELETE removes row + blob
- Permissions: every JWT route uses `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles(...)` (fails closed without it); use cases keep their own role check. The full route → roles matrix lives in `src/roles-cobertura.spec.ts`: add new endpoints there
- Session check: `VerificadorSesionService` (30 s cache per replica) makes `JwtStrategy` and the Socket.IO middleware reject a still-valid JWT whose user was deactivated or whose role changed (401 `SESION_INVALIDA` / socket `NO_AUTORIZADO`, rechecked every 30 s); clients refresh and the refresh decides
- Body validation: global `ValidacionTiposPipe` (class-validator, type-only, returns the original body). Never reject what the mobile offline queue sends today (any 4xx marks the op as a permanent error); mobile payloads are pinned in `src/shared/infrastructure/validacion/contrato-app-movil.spec.ts`
- HTTP middleware (trust proxy, request log, helmet with an API-only CSP `default-src 'none'`, compression, CORS) lives in `shared/infrastructure/config/http.ts`, used by `main.ts` and its spec; never serve HTML from the API
- Logs: in production (`NODE_ENV=production`) Nest's `ConsoleLogger` writes one JSON line per log (`main.ts`), read in Log Analytics `ContainerAppConsoleLogs_CL` via `parse_json(Log_s)`. `shared/infrastructure/observabilidad/registro-requests.ts` logs every request (context `Http`: method, route pattern, status, ms, idUsuario, rol, `abortada`); skips `/health` and OPTIONS. Never log query strings, bodies, headers, IPs or names
- Application Insights (`cmp-appinsights`, Chile Central, on the same Log Analytics workspace; daily cap 0.5 GB): `src/instrument.ts` is main.ts's FIRST import and calls `useAzureMonitor` only when `APPLICATIONINSIGHTS_CONNECTION_STRING` is set (tests/local without it send nothing). Options in `shared/infrastructure/observabilidad/opciones-azure-monitor.ts` (no Nest imports there): requests minus `/health`, OPTIONS, `/socket.io` and `POST /tracking/posiciones`; pg spans only inside a request (`requireParentSpan`, schedulers would flood it); SDK calls to Azure Monitor ignored; `LimpiezaDeTrazas` strips query strings and client IPs. `TrazaRequestInterceptor`/`FiltroExcepciones` name each request by route pattern and add only `enduser.id` + role; `FiltroExcepciones` records non-HttpException errors; `RegistroConTelemetria` (the app logger) records every `logger.error` (schedulers, Blob…) except contexts `ExceptionsHandler`/`Http` (already recorded). Logs themselves are not sent (they reach Log Analytics via stdout). The image's commit is `VERSION_APP` (Dockerfile ARG `GIT_SHA`, set by the pipeline) → `application_Version`. The mobile app's errors reach it through our own Backend, not an SDK (corporate firewall)
- DB TLS: `DB_SSL=true` always verifies the server certificate (`shared/infrastructure/config/ssl-db.ts`); Azure PG works with Node's built-in CAs, Aiven needs its project CA in `DB_SSL_CA` (file path, e.g. gitignored `certs/aiven-ca.pem`, or inline PEM). Never set `rejectUnauthorized: false`
- Before finishing: `pnpm lint` and `pnpm test`
- Deploy: Azure Container Apps (Express env) via `./scripts/deploy-azure.sh vN` — needs OCI images (buildx) and digest-based updates; env vars/secrets live in the Container App, never in the image
